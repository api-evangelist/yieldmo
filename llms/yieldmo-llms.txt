# Yieldmo

> Yieldmo is a programmatic native advertising marketplace and smart exchange, founded 2012 and headquartered in New York, operating as a supply-side platform (SSP) connecting premium publishers with advertisers across Display, Native, High-Impact, Video and CTV formats. Its YMax platform applies machine learning and attention analytics to inventory curation, contextual targeting and creative optimization.

Generated by API Evangelist from the artifacts in this repository. Yieldmo publishes no llms.txt of its own (https://yieldmo.com/llms.txt returns a robot-challenge shell; https://api.yieldmo.com/llms.txt and https://ads.yieldmo.com/llms.txt both return 404), so this file is generated, not harvested.

## APIs

- [Yieldmo DCS reporting API (MCP)](https://api.yieldmo.com/dcs/mcp): OAuth-protected campaign reporting and analytics over YMax exchange data. 19 read-only operations covering campaign performance, daily spend, creative performance, URL quality, audience segments, browser topics and advertiser attribution. Served as both an MCP server and a REST API by one FastAPI application.
- [Yieldmo JavaScript SDK](https://github.com/yieldmo/yieldmo-js-sdk/wiki): Publisher-side ad placement SDK. `window._ym.requestPageView([placementId])` requests new ads for placements already on the page, for single-page apps and infinite scroll.
- [Yieldmo Prebid.js Bid Adapter](https://docs.prebid.org/dev-docs/bidders/yieldmo.html): Header bidding adapter, biddercode `yieldmo`, banner and video, IAB GVL ID 173. Both Prebid.js and Prebid Server.
- [Yieldmo Synthetic Inventory Module](https://docs.prebid.org/dev-docs/modules/yieldmoSyntheticInventoryModule.html): Prebid.js module that creates a placement and injects the Yieldmo SDK for Synthetic Outstream ads via Google Ad Manager.

## Known gaps

- The DCS reporting API and its MCP server are live but undocumented: no reference page, no announcement, no llms.txt, and the host (api.yieldmo.com) is not linked from anywhere public.
- The OpenAPI declares no securitySchemes, no tags, no response schemas and no examples, so an agent cannot know a report's shape before calling it.
- The `WWW-Authenticate` challenge advertises a `resource_metadata` URL (`/.well-known/oauth-protected-resource/dcs/mcp`) that returns 404.
- yieldmo.com and www.yieldmo.com return HTTP 202 robot-challenge shells to every non-browser client, so the marketing and policy surface is not machine-readable.
- No status page, no changelog, no versioning scheme, no security.txt, no A2A agent card.
